# Decisiones del proyecto

1. Lo primero fue crear el `Dockerfile` y `docker-compose.yml` Django, en el cual se adaptó el ejemplo de [uv](https://docs.astral.sh/uv/guides/integration/docker/#non-editable-installs), para que el contenedor se ejecutara listo para un ambiente productivo, priorizando el tamaño de la imagen resultante. Adicionalmente, se añadió a las dependencias del proyecto `gunicorn` (utilizado como servidor WSGI), para evitar ejecutar el contenedor con `runserver`, que no es recomendado para producción. También se añadió un volumen para la base de datos SQLite, para que los datos persistan entre reinicios del contenedor.
2. Para la primera tarea del backoffice se añadió un campo `hold_reason` al modelo de `Reservation`, un nuevo estado `On Hold` y una restricción al modelo para evitar estados inconsistentes, es decir, que al cambiar de estado a `On Hold` se debe ingresar un motivo. En cuanto a la implementación, se optó por añadir al service los métodos para poder transicionar al nuevo estado, acompañando las nuevas views y modificaciones al template para poder cambiar el estado exigiendo el motivo, como se solicitaba. En cuanto a los tests, se añadieron los casos de prueba para poder abarcar la mayor cantidad de casuísticas posibles.
3. Para el cliente, se optó por React + TypeScript, ya que son las herramientas con las que cuento con más experiencia y permiten crear aplicaciones robustas y rigurosas en tipado. Para el manejo de la autenticación se creó un contexto, el cual se encarga de manejar el token que es generado al llamar la API interna. Para poder preparar la imagen del cliente, se utilizó un `Dockerfile` que utiliza `nginx` para servir la aplicación.

## Decisión descartada

Se descartó utilizar `uvicorn` con ASGI como servidor ya que la aplicación no requiere manejar peticiones asincronas, tanto para Django como para Django Ninja, por lo cual `gunicorn` con WSGI es la opción más clara. Si en el futuro se requiere de peticiones asisncronas para el servidor de Django Ninja, se debería añadir `async` a los endpoints y cambiar el servidor a `uvicorn` con `config.asgi:application` en el punto de arranque.
